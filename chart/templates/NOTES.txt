This chart does not install a Prometheus. OpenCost reads its data from one, by default at
prometheus-server.prometheus-system.svc.cluster.local:80, and that Prometheus has to scrape
OpenCost too. If OpenCost never becomes ready, or the pod below shows 0/1, start there.

Check it's working:

  kubectl -n {{ .Release.Namespace }} port-forward svc/{{ include "plutus-collector.fullname" . }} 9100:{{ .Values.service.port }}
  curl localhost:9100/healthz
  curl localhost:9100/metrics

Look for `plutus_collector_last_push_success 1` after the first push cycle (immediate on
startup, then on the schedule above). The pod is Ready (1/1) only while the last window had
cost rows; `curl localhost:9100/readyz` says why when it is not.

If `plutus_collector_last_push_success 0`, check the pod logs:

  kubectl -n {{ .Release.Namespace }} logs deploy/{{ include "plutus-collector.fullname" . }}
